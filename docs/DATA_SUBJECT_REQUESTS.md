# 정보주체 요청 처리 절차 (열람 · 정정 ·삭제 · 동의 철회)

처리하는 사람: 개인정보 보호책임자가 지정한 admin. 접수부터 처리까지 모든 단계가 감사 로그에 남는다. 처리 기한과 본인 확인 방법은 법무 검토를 거쳐 확정한다(OPEN_QUESTIONS #5·#6).

1. **접수·본인 확인**: 요청 접수번호를 만든다(예: `DSR-2026-001`). 시스템 밖에서 본인 확인을 마친다. 신분증 사본은 이 시스템에 올리지 않는다.
2. **대상 찾기**: 검색 화면에서 이름·휴대폰·이메일 **정확 일치**로 찾는다. 검색어는 감사 로그에 해시로만 남는다.

| 요청 | 화면 | API | 기록 |
|---|---|---|---|
| 열람 | 상세 → **정보주체 열람용 내보내기** (admin, 재인증) | `POST /resumes/{id}/export` (사유 = 접수번호) | `resume.export` + 사유 |
| 정정 | 상세 → 검수 화면에서 수정 후 저장 | `PUT /resumes/{id}` | `resume.update` (바뀐 필드명) |
| 삭제·동의 철회 | 상세 → **삭제 요청** | `DELETE /resumes/{id}` | `resume.delete_request` → 유예 7일 후 `resume.purge` |

3. **삭제 확인**: 관리자 → 보존·파기 화면에서 삭제 대기 목록과 파기 예정일을 확인한다. 정보주체가 즉시 파기를 요구하면 운영자가 `python -m app.cli purge`를 실행한다. 단, 유예기간 단축은 별도 승인을 받는다.
4. **백업**: 백업에 남은 사본은 백업 보존기간이 끝나야 사라진다. 그 전에 복구하더라도 파기 배치가 다시 지운다. 이 사실을 회신에 적는다.
5. **회신**: 처리 결과와 처리일을 회신하고 접수 대장을 닫는다.
